A system that runs is not a finished system. If Lambda starts failing at
2 a.m., you want to know before your users complain.

\vspace{0.5em}\noindent\textbf{Step 1. Read the logs}\par

Lambda writes logs to CloudWatch automatically thanks to the
\texttt{AWSLambdaBasicExecutionRole} policy attached in section 5.5.

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Open the
  \href{https://ap-southeast-1.console.aws.amazon.com/cloudwatch/home?region=ap-southeast-1}{CloudWatch
  console}
\item
  Choose \textbf{Log groups} and find
  \texttt{/aws/lambda/fcj-recsys-api}
\item
  Open the most recent log stream
\end{enumerate}

This is the first place to look whenever the API returns a 500. The
error message sent to users is usually trimmed; the full stack trace
lives here.

\vspace{0.5em}\noindent\textbf{Step 3. Create an error-rate
alarm}\par

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Open the
  \href{https://ap-southeast-1.console.aws.amazon.com/cloudwatch/home?region=ap-southeast-1}{CloudWatch
  console}, choose \textbf{Alarms} then \textbf{Create alarm}
\item
  Choose \textbf{Select metric}, go to \textbf{Lambda} then \textbf{By
  Function Name}
\item
  Find \texttt{fcj-recsys-api}, select the \textbf{Errors} metric,
  choose \textbf{Select metric}
\item
  Under \textbf{Conditions}:

  \begin{itemize}
  \tightlist
  \item
    \textbf{Statistic}: Sum
  \item
    \textbf{Period}: 5 minutes
  \item
    \textbf{Threshold type}: Static
  \item
    \textbf{Whenever Errors is}: Greater than \texttt{5}
  \end{itemize}
\item
  Choose \textbf{Next}, and for notifications select the
  \texttt{fcj-recsys-alerts} topic
\item
  Name the alarm \texttt{fcj-lambda-errors} and choose \textbf{Create
  alarm}
\end{enumerate}

\vspace{0.5em}\noindent\textbf{Step 4. Create a latency
alarm}\par

Repeat the steps above but select the \textbf{Duration} metric,
statistic \textbf{Average}, threshold greater than \texttt{3000}
milliseconds. Name it \texttt{fcj-lambda-latency}.

Rising latency is often an earlier signal than outright errors. When
Lambda gradually slows down, the cause is usually an inefficient
DynamoDB query or a slow Personalize response.

\vspace{0.5em}\noindent\textbf{Step 5. Set a cost alert}\par

This is the one people skip and later regret.

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Open the
  \href{https://console.aws.amazon.com/billing/home\#/budgets}{Billing
  console}
\item
  Choose \textbf{Budgets} then \textbf{Create budget}
\item
  Choose \textbf{Cost budget} and set a sensible threshold, for example
  10 USD per month
\item
  Add an alert at 80 percent of the threshold and enter your email
\end{enumerate}

A Personalize campaign bills per hour it exists. If you forget to delete
it after finishing, the cost accumulates silently. A budget alert is
your safety net for exactly that.
